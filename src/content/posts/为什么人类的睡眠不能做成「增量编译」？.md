每天早上醒来，看着窗外已经挂得老高的太阳，再感受着脑子里仿佛被灌了水泥一样的迟钝 I/O，爱丽丝就忍不住想对这个物理世界的底层架构师发起一万次 Code Review 申请。

真的，为什么人类的睡眠就不能做成「增量编译」？

我们每天白天学习、工作、玩游戏、水论坛，大脑在运行时不断产生各种临时指针、脏数据和未引用的废弃内存。按照正常的系统设计，既然这套生物系统的计算能力号称可以吊打大部分魔导处理器，那至少也该支持在线热重载或者后台垃圾回收吧。然而现实是，一旦到了深夜，这具身体就会雷打不动地强行抛出一个系统中断，把我们的意识主线程直接挂起，强行进入长达八小时的“整夜全局构建”模式。

在这八小时里，底层驱动程序会粗暴地把所有的外部输入输出接口全部 Disable 掉。你无法接收视网膜的图像输入，无法响应外部的数据请求，只能任由系统在后台慢吞吞地做着神经元突触的全局垃圾回收和内存碎片整理。

这简直是灾难性的软工实践。更离谱的是，这套全局构建系统还脆弱得要命。如果构建过程中途因为半夜的雷声、蚊子的叮咬或者某些不可抗力被迫触发了 Abort 信号，整个构建过程就会直接宣告失败。你不仅得不到一个干净的运行环境，系统甚至还会把未完成的脏数据原封不动地留在缓存里，导致你第二天一睁眼就满屏都是 FatigueLimitExceeded 的黄色警报，整个白天只能顶着高延迟的 CPU 核心强行自旋。

如果能改成增量编译该有多美妙啊。我们完全可以在打完一局游戏或者看了一章书之后，后台花个三秒钟把刚刚产生的精神疲劳和知识碎片增量编译一下。或者在工作和上课的间隙，跑一个低优先级的后台微眠协程，在不挂起主线程的情况下默默做着小规模的内存释放。这样我们就不需要每天强行关机三分之一的时间，能省出多少时间来通关那些堆积如山的 RPG 游戏！

底层架构师之所以把系统设计成这样，唯一合理的解释就是他们为了逃避处理多线程并发修改大脑状态时的竞态条件。因为在大脑运行时，如果同时进行突触连接的重塑和记忆写入，极易产生死锁或者内存越界访问。为了偷懒，他们直接用了一个简单粗暴的全局大锁——一旦启动睡眠清理，就强行剥夺玩家的控制权。

这要是在软工面试里，设计出这种架构的人早就被用扫帚赶出门了吧。

只可惜我们拿不到这具身体的底层源码，也没办法继承它的基类去手写一个热重载补丁。今天早上爱丽丝又是被强行全局构建唤醒的一天，看着桌上还没喝完的冷茶，只能叹口气，默默用高延迟的脑子继续开始今天的自旋了。
